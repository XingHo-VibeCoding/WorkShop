# WorkShop 前端设计规则（frontend-guidelines）

> **用途**：AI 在做/改 WorkShop 前端（`source/index.html`、`source/css/base.css`、`source/js/timeline.js`）前，先 Read 本文件，按下面 7 个维度逐条对照检查。
>
> **调用方法**：做/改前端前 Read 本文件 → 按 7 维度对照 → 结论写进当日打卡汇总「Skill 调用记录」段 → 相关代码注释留痕，格式 `// frontend-guidelines: <规则简称>`。
>
> **依据**：本文件规则来自 PRD.md（§4 L0 布局、§4 F1 类型色、§6.1 颜色语义）、TECH_DESIGN.md、AGENTS.md（§三.1、§十.1、§十.3）及 Day 7–11 已实装的约定，非通用空话。

---

## 1. 页面层级
- 每个页面**只有一个主标题**（现为 `.brand`「WorkShop 会议工作台」），不另立同级主标题。
- 布局 = **上栏（标题/全局操作）+ 主体（左时间线 / 右详情）+ 下栏（状态栏）+ 底部表签**（PRD §4 L0）；区块之间靠**间距分组**，不靠加边框。
- 新增区块先想清楚它属于上/主体/下/表签哪一层，不要在层与层之间插悬浮元素（除既有设置弹窗、删除弹窗外）。

## 2. 颜色与字体
- **正文 14px**、区块标题 18px 以上；字号沿用现有 CSS 变量/类，不硬开新字号档。
- **填充色 = 日程类型**：会议蓝 / 行程橙 / 课表绿 / 运动青 / 生活紫 / 待安排灰（PRD §4 F1）。个人/组织**不靠填充色**区分（用记号/外框，见 PRD §6.1）。
- 文字与背景**对比度 ≥ 4.5:1（WCAG AA）**，Day 9 已对 6 类类型色白字做过校验；**浅灰字不要放在白底上**，浅色字配深色块。
- 新增颜色前先想：它会不会破坏类型色语义或对比度。

## 3. 卡片与按钮
- 事项卡片走统一组件 `renderItemCard`（时间线/详情共用），不另写卡片拼接。
- 卡片内边距、卡片间距沿用现有 CSS 值，新增卡类型不改基线。
- 按钮必须有**默认 / 悬停(:hover) / 禁用(:disabled)** 三态；危险/主操作按钮用既有 `.btn-danger` / `.primary` 类，不另设色。
- 禁用态要有视觉提示（灰化）+ `disabled` 属性，不能只靠 JS 阻止点击。
- **悬浮提示（`title`）只加在「表意不明」的按钮上**：可见文字已自明的（如「清空筛选」「重新加载」「工作事项表」）不加 `title`，避免冗余；只有标签简短或单独看会歧义的（如「导入」「设置」「×」关闭）才加 `title` 说明作用/范围。`aria-label`（读屏器用）与可见文字一致即可，不受此条限制。

## 4. 移动端适配
- 360px 宽度下**不能出现横向滚动**；窄屏布局堆叠为单列（时间线在上、详情在下，PRD §4 L0 约束）。
- 完整响应式适配列后续，但**新增组件不得在 360px 引入横向溢出**或固定宽超出视口。
- 用 DevTools 切 360px 实测确认。

## 5. 修改前检查（动手前）
- 改 `source/` 既有文件前，先把原文件**复制成带日期的副本**进 `source/backups/YYYY-MM-DD-dayN/`（AGENTS §十.1），不覆盖既有备份。
- 先**列出具体要改什么**（哪条、从什么改成什么），逐个改、**一次只改一个**（AGENTS §三.1），不顺手优化清单外内容。
- 拿不准是否在范围内，先问，不要猜（AGENTS §一.4）。

## 6. 修改后验证（动手后）
- **桌面宽度**和**手机宽度（360px）**各看一遍。
- 确认**交互没因改样式而失效**（按钮能点、弹窗能开、键盘可达）。
- 改动既有会议/行程（删/改时间）前先列「改哪条、从什么改成什么」等用户确认才执行（AGENTS §十.3）；新增也回显写入内容。

## 7. 可访问性（余力加练）
- 交互元素**键盘可达**：Tab 能到达、Enter/Space 能触发、Esc 能关闭（弹窗沿用 Day 11 焦点管理）。
- 焦点可见：`:focus-visible` 有明显轮廓，不靠 `outline:none` 全清。
- 表单控件有 `aria-label` 或关联 `<label>`；图标按钮必有 `aria-label` / `title`。
- 语义化：用 `<button>` / `<nav>` / `<section>` / `<aside>` 等语义标签，不用 `<div onclick>` 凑。

## 成功标准（自检）
1. 文件在项目内、带 frontmatter、7 维度齐全且基于项目真实规则。
2. 真实调用 ≥1 次并留记录（打卡汇总「Skill 调用记录」段 + 代码注释）。
3. 被检查的页面/交互在 7 维度上均通过（不通过的当场修或登记）。
