### 3.6 实时协作：自动同步（2026-10-27 用户实测反馈后新增）

**用户反馈原话**：「两个用户 A、B，A 新建日程后，B 只有刷新后才能够看到。」

**根因**：不是 bug，是**设计缺失**——前端没有任何数据轮询，数据只在「初次加载 / 切周 / 点 ↻ 刷新」三个时机拉取；心跳那个 30s 定时器只上报在线状态，不拉数据。

**方案**（用户拍板：自动应用 + 提示，间隔 15 秒）：每 15s 拉一次当前周，用 `id + updatedAtRaw` 拼**签名**比对，没变就一个 DOM 都不碰；变了才重绘并提示「已同步他人的最新改动」。

| 三条保护 | 为什么必须有 |
|---|---|
| **填表中不打断** | 新建/编辑表单渲染在右侧 `#detail-body` 里，重绘详情会冲掉用户正在输入的内容 → 检测到 `#item-form` 存在就挂起，表单关闭/保存后由 `flushPendingSync()` 补应用 |
| **页面隐藏时暂停** | 切走标签页就停拉取（`document.hidden`），省云函数配额；切回立刻补一次（`visibilitychange`） |
| **当前事项被他人删/改** | 被删 → 退出详情 + 提示「你正在看的事项已被他人删除」（别让用户对着幽灵数据点编辑）；被改 → 详情静默换成新版 |

其他细节：弱网防叠加（`_syncing` 锁）；失败静默保留现有数据；**自己保存后刷新基线**（否则会把自己的改动误报成"他人的改动"）；滚动位置跨重绘保留；底栏如实标注「自动同步 15s」。

**验收（两层，2026-10-27 二次检验）**：
1. **逻辑层**：`source/temp_test/sync-logic_phase2.js` **22 项全过 / 0 失败**（vm + 可控 DOM 桩直驱 `syncTick`）：新增检测 / 无变化不重绘 / 页面隐藏不发请求 / 填表挂起+关闭后补应用 / 被删退出详情 / 被改静默换新版 / 签名与顺序无关。
2. **线上端到端**：`resource/scripts/verify-sync_phase2.js` **13 项全过 / 0 失败**，连跑两遍稳定 —— **真实前端代码 + 真实线上接口**：匿名建一条本周日程 → `syncTick()` 检测到并重绘+提示 → 删掉 → 再检测到删除 → 数据复原 11 条（`try/finally` 兜底清理，跑完核对全库条数）。它证明的不是"逻辑分支对"，而是"**线上真的能发现别人的新增**"。
3. **部署一致性**：线上 `js/timeline.js` 与本地**去 CRLF 后 md5 逐字一致**（`4574946471dc030ff9d4f4dbbc1b793a`，118409B）——排除"测的是本地、线上是旧版"。

**部署**：仅 `js/timeline.js` 一个文件（118409B 与本地逐字相符，8 个特征码核验通过）。
**过程中修掉的两个真问题**：① 每次同步重绘两遍（`render()` 之后又调 `setState()`，而它内部也 render）→ 改为统一由 `setState` 驱动；② 测试里 `apply(this, obj)` 误用（第二参必须是数组）导致假阴性——**测试自身的 bug 也曾把产品代码冤枉成"没调 showDetail"**。

## 五、复盘

### 做对了什么

1. **新端点一律加在 `items` 函数里，不新建云函数**——直接避开 10-17 那次「新函数漏配 `WORKSHOP_AUTH_SECRET` → 全员保存 401」的环境变量坑，用户控制台只多一次重传。
2. **身份墙顺序固定**：401 无令牌 → 403 非 admin → 参数校验。不向非管理员泄露参数细节（这也解释了 10-23 那次「非 admin 令牌测不出 400/404」是设计使然，不是缺陷）。
3. **审计只记动作、绝不记口令明文**——单测专门断言 detail 不含口令。
4. **双层验收**：离线 mock 控流（快、可穷举越权矩阵）+ 线上 `--live` 真库（能抓 mock 掩盖的列名/类型问题）。本轮线上全链路（addMember→resetPasscode→changePasscode→旧口令失效）正是 mock 抓不到的部分。
5. **提前识别「静默失败点」**：`audit_phase2` 的 CHECK 白名单不含新动作 → 留痕会被数据库静默拒绝。两次（set_role / Step5 三动作）都在部署前发现。

### 踩过的坑（都留了记录）

| 坑 | 教训 |
|---|---|
| mock 里漏 `calls.push(...)` → 5 项 URL/body 断言静默失败 | 「功能性全绿但链路断言红」是 mock 测试典型陷阱，先怀疑桩 |
| 环境变量名传错（`WORKSHOP_TEST_MEMBER_PASS` vs 脚本实读 `WORKSHOP_TEST_PASS`）→ 两项静默跳过 | **SKIP 行必须当信号看**，不能只看总数 |
| 自定义域名根目录直映云端 `workshop/`，带前缀反而 404 | 验线上文件别加 `/workshop`（已记入长期记忆） |
| `P="gkw""249"` 这类拆分传参导致登录 401，误判为「口令被改」 | 排障时先怀疑**传参方式**，别急着怀疑数据被改；直写即通 |
| `db/schema_phase2.sql` 约束白名单落后于线上（Step5 三动作未回写） | 控制台执行的 ALTER 必须同步回写仓库 schema，否则重建库会静默丢留痕（本次已补） |
| 首版 collab 脚本 DELETE 漏 `confirm=true` → 全返回 400，一度被读成权限问题 | **400（参数闸）与 403（权限闸）必须分清**：参数闸在权限闸之前，测权限必须先满足参数契约 |

### 阶段二最有价值的收获

「多人」的真正难点不是加字段，而是**一个人的操作如何被另一个人正确理解**：归属要能一眼认出、只读要拦得住、改角色要留痕、口令要能自救。这些都不是功能，是**信任基础**。
