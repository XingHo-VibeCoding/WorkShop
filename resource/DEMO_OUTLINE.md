## 第 1 段｜用户问题（0:00–0:40，40 秒）

**照着说：**

> 这个东西叫 WorkShop，解决的是政务人员和工作人员**排会议**的问题。两个痛点：**排会议难**，**行程不统一**。
>
> 长这样：一周七天排开，工作事项和日常事项分两张表，还能看总表。重叠的时间段会自动标出来——同表冲突标红，跨表提醒标紫。
>
> 它跑在公网，任何人都能打开；背后有一个真的数据库，刷新页面数据不会丢。

**动作**：打开首页 → 点一个色块看详情 → 点「总览」切一下 → 切回「时间线」。

## 第 2 段｜核心流程（0:40–2:20，100 秒）★ 含一次真实写入 + 刷新 + 删除

**照着说**（边做边说）：

| 步 | 动作 | 说什么 | 要让观众看到 |
|---|---|---|---|
| 2.1 | 点「+ 新建」，填一条，保存 | 「我现在排一个会」 | toast：**已保存（已同步云端）** |
| 2.2 | **按 F5 刷新** | 「关键一步：刷新。内存数据会没，数据库不会」 | 那条**还在** |
| 2.3 | 点这条 → 改时间 → 保存 | 「改一下时间」 | 时间已变 |
| 2.4 | 点「删除」 | 「删之前它会拦我一次」 | 弹窗显示标题/时间/地点 + 「删除后无法恢复」 |
| 2.5 | 确认删除 | 「确认才真删」 | 该条消失；toast 提示已删除 |
| 2.6 | 切到 `/api/items` 标签页刷新 | 「绕开页面，直接问接口」 | 裸 JSON，刚才那条已不在 |

**收尾一句**：

> 新建 → 刷新还在 → 改 → 删（要确认）→ 接口查不到。这五步证明它不是内存态，是真的落库了。

> **降级预案**：万一步骤报错，直接展示历史证据——09-29、09-30 写入的记录，今天（10-06）仍能读到。**隔天还能读到 = 持久化已自证**。

## 第 3 段｜提示词改写（2:20–3:20，60 秒）

**照着说**：

> 28 天下来我学到的最重要一条：**跟 AI 说"想要什么效果"没用，要说"边界在哪、不许怎么做"。**
> 举两个真实例子：

| 我原来的说法 | 改成了 | 为什么 |
|---|---|---|
| 「防止用户重复提交」 | 「A 内容去重 + B 幂等键双保险；冲突返回 **409 且 message 是中文**」 | 只说"防重复"只会得到一种方案；同内容重试和误点两次是两件事 |
| 「把接口代码理一理」 | 「控制器里**不许出现 fetch**，数据访问全部收进 `db.js`」 | "理一理"没法验收；写成硬边界后，一条 grep 就能验完 |

**收尾一句**：

> 判断标准很简单：**效果描述没法验收，边界描述一条命令就能验完。**

## 第 4 段｜验证方式（3:20–4:20，60 秒）★ 现场敲命令

**照着敲**（最有说服力的一段）：

```bash
curl -s https://workshop-d4g02a7z81ff51a63-1d496602788.ap-shanghai.app.tcloudbase.com/api/health
curl -s https://workshop-d4g02a7z81ff51a63-1d496602788.ap-shanghai.app.tcloudbase.com/api/items
node resource/scripts/verify-project.js
```

**照着说**：

> 第一条证明后端活着，第二条是数据库里真实的 11 条数据，
> 第三条是我自己写的发布前检查——**19 个判定点，今天跑出来 22 项全 PASS**。
> 它专门拦我历史上真踩过的坑：CORS 是不是放行任意域名、错误响应是不是恒 200、云函数有没有漏传依赖文件、密钥有没有进仓库。
>
> 完整验收在 `resource/ACCEPTANCE_DAY28.md`，附录 J 十项：**9 项 PASS、1 项部分执行、0 项 FAIL**。
> 那个"部分执行"是 CloudBase 的用量数字——CLI 查不到，只能控制台看，**没查到的我就写"未执行"，不写 PASS**。

## 第 5 段｜平台限制（4:20–4:50，30 秒）

**照着说**（诚实比漂亮更可信）：

| 限制 | 实情 |
|---|---|
| 环境是体验版 | 免费额度有限，**2027-03-27 到期**，到期前要决定续费或迁移 |
| 云函数部署 | 改了依赖文件必须**一起上传**，否则加载阶段就崩（这个坑我踩了 **3 次**） |
| 数据库方言 | 是 **PostgreSQL** 不是 MySQL，一开始按 MySQL 写全被拒 |
| 本机环境 | `git push` 在本机常被 TLS 掐断，得换网络手动推 |
| 数据备份 | **没有自动备份**，现在靠手动导出 |

## 第 6 段｜后续优化计划（4:50–5:10，20 秒）

**照着说**：

> 接下来想做的，按性价比排：
> 1. **数据导出按钮**（CSV / JSON 一键导出，顺手解决备份问题）
> 2. **完成率统计**（排了多少、完成多少，一眼能看）
> 3. **软删除**（现在删了就没了，加个 `is_deleted` 能找回）
>
> 明确不在 v1.0 范围的：多人协作、图片识别导入、会议提醒、移动端完整适配——这些写在 PRD §6 里，不是缺陷，是边界。

**收尾一句（结营点题）**：

> 28 天最大的认知改变：**「完成」不再由 AI 宣布，而由一条能复现的命令证明。**
